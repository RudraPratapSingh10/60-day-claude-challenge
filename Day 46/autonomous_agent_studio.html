Architecture overview

    
Each round makes real, sequential API calls — nothing is precomputed. The Planner and Executor run once to establish requirements and a first draft. From there, the loop repeats Evaluator → Critic → Memory Manager → Safety Monitor → stop-check → Improver until the stop-check breaks the loop, at which point control branches to the Final Reviewer.

    

      
Planner
Turns your one-line description into concrete responsive requirements: breakpoints to target, layout strategy, and constraints the Executor must satisfy.

      
Executor
Writes the first working HTML/CSS/JS draft of the component from the Planner's requirements.

      
Evaluator
Scores the current draft 0–10 against a responsiveness rubric, with a reasoned breakdown — this score is what the stop-check reads.

      
Critic
Finds concrete, specific responsive-design flaws in the current draft that a raw score alone wouldn't surface.

      
Improver
Rewrites the draft using the Evaluator's score, the Critic's flaws, and Memory Manager's notes — never starts from scratch.

      
Memory Manager
Keeps a running summary of what's worked and what's failed across rounds, so the Improver doesn't repeat old mistakes.

      
Safety Monitor
Screens each draft for unsafe patterns (inline script injection risk, unsafe eval, external resource pulls) independent of quality scoring.

      
Final Reviewer
Runs once, after the loop stops, to do a last polish pass and explain — in plain terms — why the run ended where it did.

    

    
The stop-check runs every round, in fixed order: first plateau (score gain ≤0.3 for 2 straight rounds), then threshold (score ≥ target), then a hard iteration cap as a safety fallback only — never the intended ending. Whichever fires first is logged and shown in the final summary.

  


  

    
Extension ideas

    

      
Parallel evaluatorsRun 2–3 Evaluator calls per round with different rubrics (a11y, performance, visual) and average the scores for a more robust stop-check.

      
Human-in-the-loop gateLet a person approve or reject the Improver's draft before it becomes the new baseline, instead of auto-accepting every round.

      
Multi-component runsQueue several component descriptions and let the Planner sequence them, sharing Memory Manager notes across the whole batch.

      
Cost/latency trackingLog token estimates and wall-clock time per agent call to compare orchestration strategies on efficiency, not just quality.

      
Adversarial CriticGive the Critic a harsher persona (e.g. "assume this ships to 10M mobile users") to stress-test drafts before they're accepted.

      
Branch on Safety MonitorCurrently Safety Monitor only flags; wire it to force an immediate Improver pass regardless of score if it flags anything.

    

  


  

    
Further prompts for building more advanced autonomous systems

    
"Add a Human Approval agent between Improver and Evaluator that pauses the loop and asks the user to approve, edit, or reject the draft before scoring resumes."

    
"Turn the Planner into a multi-task planner: accept a list of 3 components, and orchestrate the whole pipeline once per component, reusing a shared Memory Manager."

    
"Add a second Evaluator with an accessibility rubric running in parallel with the responsiveness Evaluator, and require both to pass threshold before stopping."

    
"Replace the numeric stop threshold with an LLM-as-judge Final Reviewer that can override an early stop if it disagrees with the Evaluator's score."
